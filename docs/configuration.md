# Конфигурация

Всичко, което се настройва през променливи на средата, на четири групи: какво от `.env` стига до приложението, какво
от `.env` ползват останалите части на сървъра (Caddy, Litestream, скриптовете), какво е зададено от образа и
`docker-compose.yml` и какво е само за разработка и тестове. Как се пуска на сървър е във [Внедряване](self-hosting.md),
а `.env.example` е шаблонът за `.env`. Тест (`apps/server/test/config.test.ts`) пази всяко име, което кодът чете,
описано тук.

## `.env` → приложението

`docker-compose.yml` подава на приложението само тези (изрично изброени). Друга променлива в `.env` до него не стига.

| Променлива                              | По подразбиране                 | Значение                                                                                                                                              |
| --------------------------------------- | ------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| `OPERATOR_NAME`, `OPERATOR_ADDRESS`     |                                 | Кой поддържа сайта; показва се в политиката за поверителност и условията (името е задължително в продукция, адресът — не)                             |
| `CONTACT_EMAIL`                         | `privacy@almanac.bg`            | Адрес за контакт в правните страници и имейлите (по подразбиране е от `packages/shared/src/brand.ts`, не от `DOMAIN`: на друг домейн го задай)        |
| `EMAIL_PROVIDER`, `HOSTING_PROVIDER`    |                                 | Посочени в политиката за поверителност като обработващи данни                                                                                         |
| `PROXY_PROVIDER`                        |                                 | Също в политиката, ако е зададен: проксито на Cloudflare, през което минава всяка връзка, и бисквитката му след проверка дали посетителят е човек     |
| `BACKUP_PROVIDER`, `INBOX_PROVIDER`     |                                 | Също в политиката, ако са зададени: бекъпите извън сървъра и кой пренасочва писмата до `CONTACT_EMAIL` (празно без пренасочване)                      |
| `MAILBOX_PROVIDER`                      |                                 | Също в политиката, ако е зададен: пощата, в която писмата до `CONTACT_EMAIL` пристигат (пренасочени или направо)                                      |
| `SMTP_URL`                              |                                 | Напр. `smtp://user:pass@host:587?requireTLS=true` (без `requireTLS` сървърът предупреждава). Без него → имейлите се печатат в конзолата               |
| `MAIL_FROM`                             | `АЛМАНАХ <no-reply@almanac.bg>` | Адрес на подателя (по подразбиране от `brand.ts`, не от `DOMAIN`)                                                                                     |
| `EMAIL_EVENTS_SECRET`                   |                                 | Тайната в адреса за отчети от Scaleway (`/api/email-events/<тайна>`), поне 32 знака. Без нея → изключено                                              |
| `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY` |                                 | Ключовете за известията на устройството (web push); без тях Настройки не ги предлагат. `cli.mjs vapid-keys >> .env` ги прави                          |
| `SENTRY_DSN`                            |                                 | Sentry проект за отчети за грешки; без него → грешките отиват само в лога                                                                             |
| `SENTRY_LOGS`                           |                                 | `off`: логът остава само на сървъра. Иначе (със `SENTRY_DSN`, в продукция) отива и в Sentry Logs, без имейли, IP адреси и имена или кодове в адресите |
| `SENTRY_BROWSER_DSN`                    |                                 | Отделен Sentry проект (или ключ) за отчетите от браузъра — единственият DSN в страницата; без него сривовете в браузъра отиват в лога на сървъра      |
| `SOURCE_URL`                            |                                 | Публичното хранилище, към което води линкът във футъра („Изходен код“)                                                                                |
| `BOT_FILL_SECONDS`                      | `8`                             | Изчакване в опашката, преди ботове да заемат празните места; `off` изключва ботовете                                                                  |
| `BOT_FILL_BUSY_SECONDS`                 | `20`                            | Същото, докато друг човек е онлайн и свободен (не е в мач, опашка или стая): тогава си струва да го изчакаме                                          |
| `PUBLIC_QUEUES`                         | `all`                           | Класирани опашки, в които играчите могат да влизат (`all` или списък от `duel`, `teams`, `squad`, `royale`)                                           |
| `EVENING_AT`                            | `21:00`                         | Кога започва Вечерният Роял, софийско време (`ЧЧ:ММ`); `off` го изключва                                                                              |
| `BACKUP_KEEP_DAYS`                      | `3`                             | Колко дневни копия на базата да се пазят (всяко е пълно копие на същия диск: виж [Поддръжка → Диск](operations.md#диск))                              |

## `.env` → сървърът около приложението

| Променлива                                          | По подразбиране              | Значение                                                                                                                       |
| --------------------------------------------------- | ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| `DOMAIN`                                            | `almanac.bg`                 | Домейнът: за него Caddy взема сертификат, а приложението получава `APP_URL=https://<DOMAIN>`                                   |
| `HSTS_PRELOAD`                                      |                              | `; preload` в HSTS заглавката на Caddy (само след заявка в hstspreload.org и за домейн, чиито поддомейни са на HTTPS завинаги) |
| `IMAGE`                                             | `ghcr.io/almanac-bg/almanac` | Откъде `deploy/deploy.sh` и `deploy/rollback.sh` теглят образа (от свой fork: `ghcr.io/<организация>/<хранилище>`)             |
| `COMPOSE_PROFILES`                                  |                              | `backup` пуска и Litestream                                                                                                    |
| `BACKUP_BUCKET`, `BACKUP_ENDPOINT`, `BACKUP_REGION` |                              | Къде Litestream пази бекъпите (S3-съвместимо object storage)                                                                   |
| `BACKUP_ACCESS_KEY_ID`, `BACKUP_SECRET_ACCESS_KEY`  |                              | Ключовете за него                                                                                                              |

## Зададени от образа и `docker-compose.yml`

В продукция идват от `Dockerfile` и `docker-compose.yml`, не от `.env`. Без Docker (при разработка) важат
стойностите по подразбиране.

| Променлива           | В продукция                       | Без Docker                                         | Значение                                                                                        |
| -------------------- | --------------------------------- | -------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| `NODE_ENV`           | `production`                      |                                                    | Продукция: иска `OPERATOR_NAME` и дава на мачовете време при спиране (`DRAIN_SECONDS`)          |
| `PORT`               | `3001`                            | `3001`                                             | Порт на сървъра                                                                                 |
| `DB_PATH`            | `/data/quiz.db`                   | `apps/server/data/quiz.db`                         | SQLite файл (създава се и се мигрира автоматично)                                               |
| `QUESTIONS_PATH`     | `/app/private/questions.json`     | `private/questions.json`, иначе примерната банка   | Банката с въпроси (виж [Добавяне на въпроси](questions.md)); в продукция без нея сървърът спира |
| `APP_URL`            | `https://<DOMAIN>`                | `http://localhost:5173`                            | Публичният адрес (origin) в линковете в имейлите                                                |
| `COOKIE_SECURE`      | `true`                            | `true`, когато `APP_URL` е `https:`, иначе `false` | Бисквитката на сесията само по HTTPS                                                            |
| `TRUST_PROXY`        | `loopback, uniquelocal`           | `loopback`                                         | Express `trust proxy`: на кои proxy сървъри да се вярва за адреса на посетителя                 |
| `APP_RELEASE`        | commit-ът (от `deploy/deploy.sh`) |                                                    | Версия в отчетите за грешки                                                                     |
| `DRAIN_SECONDS`      | `330`                             | `0`                                                | При спиране: колко време имат текущите мачове да завършат (под `stop_grace_period: 6m`)         |
| `BACKUP_DIR`         | `/data/backups`                   | `backups` до базата                                | Дневни копия на базата; `off` ги изключва                                                       |
| `UV_THREADPOOL_SIZE` | `8`                               | `4`                                                | Нишките на libuv, които хеширането на пароли дели с четенето на файлове                         |

## Разработка и тестове

| Променлива                   | Значение                                                                                                            |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| `API_URL`                    | Къде `npm run dev` праща `/api` и връзката на играта (по подразбиране `http://localhost:3001`): сървър на друг порт |
| `GAME_TIME_SCALE`            | Умножава всички таймери в играта (тестовете я пускат бързо)                                                         |
| `MAIL_OUTBOX`, `PUSH_OUTBOX` | Писмата и известията се записват като JSON файлове в тази папка, вместо да се пращат                                |
| `ERROR_OUTBOX`               | Всяка грешка, която сървърът отчита, се дописва и в този файл: тест пада на грешка, която не е очаквал              |
| `PUSH_QUIET`                 | `off` маха нощната тишина на известията (тестове по всяко време)                                                    |
| `SQL_LOG`                    | Папка за лог на всяка SQL заявка (проверката на плановете на заявките в `npm test`)                                 |
| `TEST_TARGET`                | `dist`: сървърните тестове пускат продукционния bundle вместо кода                                                  |
| `E2E_PORT`, `E2E_TIME_SCALE` | Портът и скоростта на сървъра в браузърните тестове (`3210`, `0.15`)                                                |
| `E2E_ENGINES`, `E2E_FIREFOX` | `webkit,firefox` добавя браузърите на Safari и Firefox; `E2E_FIREFOX=app` кара инсталирания Firefox                 |
| `BROWSER_PATH`               | Браузър на Chromium (Brave, Chromium, Edge…) за браузърните тестове вместо системния Chrome                         |

Името на марката е в `packages/shared/src/brand.ts`.
