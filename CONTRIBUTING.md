# Принос към АЛМАНАХ

Благодарим, че помагаш! Доклади за бъгове, поправки и подобрения — всичко е добре дошло. Дискусиите, issues и pull
request-ите тук са на български (английският също е добре дошъл); кодът и коментарите в него са на английски.

## Първи стъпки

Нужен ти е само Node 24+ (базата данни е SQLite, вградена в Node), на macOS или Linux (на Windows — WSL):

```bash
npm ci
npm run dev        # сървър на :3001, уеб приложение на :5173
```

Ако портовете са заети: `PORT=3111 API_URL=http://localhost:3111 npm run dev`, а за браузърните тестове `E2E_PORT`
(и `E2E_OUTPUT`, за да не пишат в същите папки като друг пуск; всички настройки са в [Конфигурация](docs/configuration.md)).

Току-що клонираният код играе с примерна банка от 120 въпроса; банката на almanac.bg е частна. Първият профил, който
регистрираш при разработка, е администратор, така че можеш да пробваш и `/admin`. Структурата на кода е описана в
[README](README.md#структура-на-кода), а останалото — в [docs/](docs).

## Преди да отвориш pull request

- `npm run lint`, `npm run typecheck` и `npm test` минават (`npm run format` оправя форматирането и реда на импортите;
  във VS Code препоръчаното разширение Biome го прави при запис). При промени в уеб приложението пусни и браузърните
  тестове:
  `BROWSER_PATH=<път до браузър, базиран на Chromium> npm run test:browser` (CI ги пуска с Chrome).
- Новото поведение идва с тест: `apps/server/test` (test runner-ът на Node) за сървъра и правилата на играта,
  `apps/web/e2e` (Playwright) за цели сценарии в браузъра.
- Промяна в базата данни е нова миграция, добавена в края на списъка в `apps/server/src/db.ts`; никога не редактирай
  съществуваща (живите бази вече са я изпълнили). Когато може, тя е съвместима (`compatible`: нова таблица или колона,
  която предишната версия просто не ползва), за да може връщане към предишната версия без възстановяване на базата;
  стойностите, които новият код извлича от други, попълва `repair()` в същия файл.
- Протоколът между клиента и сървъра (`packages/shared/src/protocol.ts`) се променя само с добавяне: ново поле или
  събитие, а не преименуване или премахване в същото обновяване. След деплой отворените табове зареждат новата версия
  чак когато играчът не е в мач, а дотогава говорят с новия сървър със стария код. Промяна, която стар клиент не може
  да следва (приложенията в магазините се обновяват след дни), вдига `PROTOCOL` в `packages/shared/src/client.ts` и
  излиза по реда в [docs/maintainers.md → Протокол](docs/maintainers.md#протокол).
- Pull request-ите да са фокусирани: една промяна, обяснена в описанието.

## Commits и pull requests

Pull request-ът се слива със squash: заглавието и описанието му стават commit-ът в `main`. Затова заглавието следва
[Conventional Commits 1.0](https://www.conventionalcommits.org/en/v1.0.0/), а CI го проверява с commitlint
(`commitlint.config.mjs`, проверката „PR title“):

    type(scope): summary

- **type**: `feat` (нещо ново за играчите или поддържащите), `fix` (поправка), `perf`, `refactor`, `docs`, `test`,
  `build`, `ci`, `chore`, `revert`. От него зависи следващата версия, а `feat`, `fix`, `perf` и `revert` влизат в
  бележките към изданието.
- **scope** (по желание): къде е промяната — `web`, `mobile`, `server`, `client`, `shared`, `bank`, `deploy`, `ci`,
  `docs`, `deps`, `e2e`, `security`, `release`.
- **summary**: на английски, в повелително наклонение, с малка буква и без точка; целият ред е до 72 знака (CI пуска до 100, за заглавията на Dependabot). Казва
  какво се променя за човека, който ще го прочете в бележките към изданието: `fix(web): keep entrances still under
  reduced motion`, а не `fix: bug`.
- Промяна, която иска действие от поддържащ сървъра (настройка, преместени данни, премахнато нещо, на което някой
  разчита), е несъвместима: `!` след типа (`feat(server)!: …`) и ред `BREAKING CHANGE: какво да се направи` в
  описанието. Тя вдига MAJOR версията.
- Описанието казва защо и как е проверено, на редове до 72 знака.
- Клонът е `type/short-name` на английски (`fix/reduced-motion-entrances`).

`CHANGELOG.md`, версиите и таговете не се пипат на ръка: release-please ги прави от тези заглавия при изданието
([docs/maintainers.md → Издания](docs/maintainers.md#издания)).

## Приложението

`apps/mobile` е приложението за iOS и Android: Expo SDK 58 (React Native 0.88) със същото ядро като сайта
(`packages/client`, `packages/shared`).

- **Инсталира се отделно**, не с workspaces на корена: `cd apps/mobile && npm ci`. Така има React и TypeScript на
  React Native, а не на сайта, и сървърът и образът му не теглят React Native. Metro билдва `packages/*` от изходния им
  код, а каквото те внасят (react, zustand, socket.io-client), търси в приложението: един React (`metro.config.js`).
- **Пускане:** нужен е development build — Xcode за iOS, Android Studio за Android, или услугата на Expo за билдове.
  `npx expo run:ios` или `npx expo run:android`, после `npm start`. Срещу локален сървър:
  `EXPO_PUBLIC_API_URL=http://192.168.1.5:3001 npm start`.
- **Проверки:** `npm run typecheck`, `npm test`, `npm run bundle` (двете платформи, както ги билдва магазинът). CI ги пуска
  в задачата `app`.
- **Пакети:** `npx expo install <пакет>` избира версията, която SDK-то очаква. Нов SDK: `npx expo install expo@^NN --fix`.
- **Линковете:** след промяна в `APP_PATHS` (`packages/shared/src/routes.ts`) — `npm run app-links` в корена. Тестът на
  приложението пада, докато филтрите му се различават.
- **Иконите** се рисуват от `favicon.svg`, заедно с тези на сайта: `npm run icons -w @almanac/web`.
- Целият текст минава през `<T>` (`src/ui/Text.tsx`), който расте с размера на текста на телефона, без таван.

## Стил

- Следвай кода около промяната: именуването, колко коментари има и идиомите му. Коментарите казват _защо_, а не
  какво.
- Текстът, който играчите виждат, е на **български** и е **неутрален по отношение на пола**: без мъжки или женски
  форми, когато се обръщаш към играча („Ти си в стая“, „Имаш покана“ — а не „Поканен си“, „готов“, „влязъл“).
- Уеб приложението трябва да работи на телефон с ширина 320 px (без хоризонтално скролиране), с цели за докосване от
  44 px, достъп от клавиатура и етикети за екранни четци.
- Сървърът държи правилата: за часовника, отговорите и точките никога не се вярва на клиента.
