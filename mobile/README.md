# The app

АЛМАНАХ for iPhone and Android: the game's site (almanac.bg) in the phone's web view, made with Capacitor. The game
itself is the web client; a change to it reaches the app at once, with no new build and no store review. The app only
adds what a page can't do well on a phone, through Capacitor's plugins, which the page calls (`web/src/lib/app.ts`,
`phone.ts`, loaded only in the app):

- **notifications** from Apple (APNs) and Google (Firebase Cloud Messaging), sent by the server
  (`internal/push/phones.go`) to the token the phone gives (`POST /api/push/phone`);
- **sharing** through the phone's share sheet, **a touch felt** on an answer, Android's **back button**;
- **links** to the game's pages on almanac.bg opened in the app (the site's `/.well-known/apple-app-site-association`
  and `assetlinks.json`, `internal/server/applinks.go`; Android's list of them is in `AndroidManifest.xml`, kept the
  same by a test); the server's own pages (privacy, a mail's „no more of these“) stay in the browser;
- a page of its own when there's no connection (`www/offline.html`).

A new build is needed only when this folder changes (a plugin, the icon, the native settings, the links it opens).
The page that has been open for days in the app's web view loads itself anew after a deploy, at a moment that costs no
play (`web/src/fresh.ts`). `server.url` in `capacitor.config.json` ends in `/`: an iPhone's web view takes every
address that starts with it, letter for letter, for the app's own (with its bridge), and without the slash
`almanac.bg.example.com` would be one.

## Build

```bash
cd mobile && npm ci && npx cap sync      # after any change here or a new plugin
```

- **iOS:** Xcode, with the team's Apple ID in Settings → Accounts. `scripts/ios-upload.sh` builds and uploads to App
  Store Connect (TestFlight). The team has no registered iPhone, so Xcode's own Product → Archive fails for want of a
  development profile: the script archives unsigned and has the export sign for the App Store. The entitlements
  (push, links) are `App/App.entitlements` for Debug (push sandbox) and `App/AppRelease.entitlements` for Release.
- **Android:** Android Studio (its SDK). `cd android && ./gradlew bundleRelease` makes
  `app/build/outputs/bundle/release/app-release.aab`, signed with the upload key that
  `~/.config/almanac/android-upload.properties` (or the file `ALMANAC_UPLOAD_KEY` names) gives:

  ```properties
  storeFile=/Users/<you>/.config/almanac/android-upload.jks
  storePassword=…
  keyAlias=upload
  keyPassword=…
  ```

  The keystore and its password live outside the repository (and in the password manager). Lost, it's replaced by
  Play Console → App signing → Upload key → Request reset, with a new key's certificate
  (`keytool -export -rfc -alias upload`).

Icons and splash screens come from `assets/` (`npm run icons`).

## Keys the server needs for notifications

Without them the app runs, and offers no notifications on that platform (`/api/push/phone` is refused, and the page
hides the switch).

- **iPhone:** an APNs key from developer.apple.com → Keys (Apple Push Notifications service), as
  `/etc/almanac/apns.p8`, with `APNS_KEY_FILE`, `APNS_KEY_ID`, `APNS_TEAM_ID` in `/etc/almanac/env`.
- **Android:** a Firebase project with the Android app `bg.almanac.app`: its `google-services.json` goes in
  `android/app/` for the build (git-ignored), and a service account key (Project settings → Service accounts) as
  `/etc/almanac/fcm.json`, with `FCM_CREDENTIALS_FILE`.

## Trying it against a local server

Point the copied config at the server (it's regenerated by `npx cap sync`, so nothing stays): in
`ios/App/App/capacitor.config.json` (or `android/app/src/main/assets/capacitor.config.json`) set
`"server": {"url": "http://localhost:8080", "cleartext": true}`, then build and run. A simulator reaches the Mac's
localhost as it is; an Android emulator needs `adb reverse tcp:8080 tcp:8080`.
